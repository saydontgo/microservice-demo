# 鉴权与幂等设计

## 1. 鉴权目标

- 确保只有登录用户能访问业务接口。
- 确保买家不能访问卖家接口，卖家不能访问买家接口。
- 确保用户只能操作自己的资源。

## 2. Token 内容

```json
{
  "userId": 10001,
  "role": "SELLER",
  "expiresAt": 1770000000
}
```

## 3. 权限校验

| 接口类型 | 要求角色 |
| --- | --- |
| `/api/buyer/**` | `BUYER` |
| `/api/seller/**` | `SELLER` |
| `/api/auth/logout` | 任意登录用户 |

## 4. 资源归属校验

| 资源 | 校验规则 |
| --- | --- |
| 买家资料 | `buyer_profiles.user_id = current_user_id` |
| 买家订单 | `orders.buyer_id = current_user_id` |
| 卖家商品 | `products.seller_id = current_user_id` |
| 卖家订单 | `orders.seller_id = current_user_id` |

## 5. 幂等适用范围

| 操作 | 是否需要 | 原因 |
| --- | --- | --- |
| 注册 | 是 | 防止重复创建账号 |
| 登录 | 否 | 登录可重复执行 |
| 充值 | 是 | 防止重复加余额 |
| 下单支付 | 是 | 防止重复扣款和建单 |
| 退款 | 是 | 防止重复退款 |
| 一键发货 | 是 | 防止重复发货 |
| 确认收货 | 是 | 防止重复状态变更 |
| 更新资料 | 可选 | 重复提交影响较低 |

## 6. 幂等处理流程

1. 读取 `Idempotency-Key`。
2. 计算请求参数摘要。
3. 尝试创建幂等记录。
4. 如果 Key 已存在且参数摘要一致，返回首次响应。
5. 如果 Key 已存在但参数摘要不一致，返回幂等冲突。
6. 业务处理成功后保存响应摘要。
