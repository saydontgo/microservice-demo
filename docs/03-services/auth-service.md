# Auth Service 设计

## 1. 职责

- 用户注册。
- 用户登录。
- Token 签发和校验。
- 退出登录。
- 角色鉴权。

## 2. 数据依赖

| 依赖 | 用途 |
| --- | --- |
| `users` | 账号、密码摘要、角色 |
| `buyer_profiles` | 买家注册时初始化资料 |
| `seller_profiles` | 卖家注册时初始化资料 |
| Redis `auth:token:{token}` | 登录态 |

## 3. 注册流程

1. 校验 `username` 唯一。
2. 校验 `role` 必须为 `BUYER` 或 `SELLER`。
3. 密码加盐摘要后写入 `users`。
4. 根据角色写入买家或卖家资料。
5. 返回用户 ID。

## 4. 登录流程

1. 根据 `username` 查询用户。
2. 校验密码摘要。
3. 校验登录选择身份和账号角色一致。
4. 生成 Token。
5. 写入 Redis 登录态。
6. 返回 Token 和过期时间。

## 5. 鉴权输出

中间件向后续服务透传：

| 字段 | 说明 |
| --- | --- |
| `user_id` | 当前登录用户 ID |
| `role` | 当前用户身份 |
| `token` | 原始 Token |

## 6. 异常处理

- 用户名不存在和密码错误统一返回登录失败，避免枚举账号。
- Token 不存在或过期返回 401。
- 角色不匹配返回 403。
