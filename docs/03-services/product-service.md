# Product Service 设计

## 1. 职责

- 商品创建和更新。
- 商品名前缀搜索。
- 卖家商品列表筛选。
- 商品状态流转。
- 商品下架判断。

## 2. 商品可见性

| 场景 | 可见状态 |
| --- | --- |
| 买家商品浏览 | `1`（在售）、`2`（预售中） |
| 卖家商品管理 | 当前卖家的全部非删除商品 |
| 下架中商品 | 买家不可见，卖家可见 |

## 3. 商品状态规则

- `1`（在售） 商品可下架为 `3`（正在下架）。
- `3`（正在下架） 商品只有在无未完成订单后才可变为 `4`（已下架）。
- `2`（预售中） 商品库存展示为 0，但卖家可以补库存。
- `4`（已下架） 商品可在补库存后重新上架。

## 4. 搜索规则

商品名只支持前缀匹配：

```sql
WHERE product_name LIKE CONCAT(?, '%')
```

为避免低效模糊查询，不支持包含匹配：

```sql
WHERE product_name LIKE CONCAT('%', ?, '%')
```

## 5. 卖家商品管理指标

Product Service 聚合以下信息返回给前端：

- 商品名和商品 ID。
- 商品状态。
- 指定时间范围内成交金额。
- 指定时间范围内退款金额。
- 退款率。
- 库存展示值。
- 是否有未发货订单。
- 是否可下架。

## 6. 数据依赖

| 表 | 用途 |
| --- | --- |
| `products` | 商品基础信息 |
| `product_inventory` | 库存展示 |
| `product_daily_stats` | 商品成交和退款指标 |
| `orders` | 未完成订单判断 |
