# Order Service 设计

## 1. 职责

- 创建订单。
- 查询订单。
- 退款。
- 一键发货。
- 确认收货。
- 维护订单状态机。

## 2. 下单事务

事务内操作顺序：

1. 锁定商品记录，确认商品可买。
2. 校验数量不超过 100。
3. 校验总金额不超过 100,000,000 元。
4. 锁定买家资料并校验余额。
5. 锁定库存记录。
6. 扣减买家余额。
7. 对非预售商品预占库存。
8. 创建订单。
9. 创建支付流水。
10. 更新卖家成交总额和统计表。

## 3. 发货事务

1. 校验卖家拥有该商品。
2. 查询所有未发货订单。
3. 计算总发货数量。
4. 锁定库存。
5. 校验库存充足。
6. 更新订单为 `2`（配送中）。
7. 更新库存数量。

## 4. 退款事务

1. 锁定订单。
2. 校验订单属于当前买家。
3. 校验状态为 `1`（已下单未发货）。
4. 增加买家余额。
5. 减少卖家成交总额。
6. 更新订单为 `4`（已退款）。
7. 创建退款流水。
8. 更新统计表退款金额。

## 5. 确认收货事务

1. 锁定订单。
2. 校验订单属于当前买家。
3. 校验状态为 `2`（配送中）。
4. 更新状态为 `3`（已收货）。
5. 设置 `is_deal_completed = 1`。

## 6. 幂等点

| 操作 | 幂等键 |
| --- | --- |
| 创建订单 | `Idempotency-Key` |
| 退款 | `Idempotency-Key` |
| 一键发货 | `Idempotency-Key` |
| 确认收货 | `Idempotency-Key` |
